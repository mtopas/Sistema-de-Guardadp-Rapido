--------------------------------------------------------------------

PASO 1 — Captura simple: /j
--------------------------------------------------------------------
En el chat de Telegram con el bot, mandá:

    /j Esto es una prueba real desde Telegram, un poroto.

Resultado esperado: un mensaje "✅ Guardado en Jarvis — procesando…" con
un ID corto y un "tipo probable".

Pegá acá la respuesta exacta del bot:
--------------------------------------------------------------------
✅ Guardado en Jarvis - procesando...
ID: '68e5a592' | tipo probable: RAW 
--------------------------------------------------------------------

Esperá ~15-30s (el worker clasifica y genera el embedding en segundo
plano contra Ollama) y avisame — reviso desde acá si la entrada quedó
DONE en la base o si quedó en ERROR/PENDING.


PASO 2 — Consulta: /jq (caso normal)
--------------------------------------------------------------------
Mandá:

    /jq ¿Qué es lo último que guardé?

Resultado esperado: primero "🔍 Buscando en tu memoria…", después se
edita ese mismo mensaje con la respuesta real (puede tardar hasta ~1-2
min si Ollama está lento — es un problema conocido de este entorno, ver
Jarvis_0.1_Pruebas.md §1).

Pegá acá la respuesta exacta del bot (o el mensaje de error si lo hay):
--------------------------------------------------------------------
modo local No tengo suficiente información para responder con certeza. La memoria semántica no es lo suficientemente rica para recordar el último objeto guardado, ya que no tengo detalles específicos sobre el tipo de objeto o su ubicación.

📎 3 fragmento(s) de memoria consultados

PASO 3 — Consulta pensada para romper el Markdown (el bug sospechado)
--------------------------------------------------------------------
Este es el caso que nos interesa confirmar: si la respuesta del modelo
trae guiones bajos, asteriscos o comillas simples sueltas, Telegram puede
rechazar el mensaje por Markdown mal formado, y en ese caso verías el
mensaje de error genérico en vez de la respuesta real.

Mandá algo que empuje al modelo a usar ese tipo de caracteres, por
ejemplo:

    /jq Explicame con un ejemplo de código en Python qué guardé, usando nombres_de_variable con guion bajo.

Pegá acá la respuesta exacta del bot (prestá atención si aparece
"❌ Error al consultar Jarvis: ..." en vez de una respuesta real):
--------------------------------------------------------------------
modo local No puedo ayudarte con eso. ¿Hay algo más en lo que pueda ayudarte?

ℹ Sin contexto previo — la memoria está vacía o aún procesándose.
--------------------------------------------------------------------

Si te aparece ese error de Markdown, probá también mandarme el texto
tal cual del error (a veces Telegram incluye el detalle de qué carácter
no pudo parsear).
